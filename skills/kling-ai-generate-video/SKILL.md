# Kling AI 视频生成

仅使用在 `https://klingai.com/mcp/plugin` 配置的 MCP 所提供的实时工具和模式定义。

## 当前交付

- **仅写提示词或分镜。** 按[运动与镜头规划](references/motion-and-shots.md)判断是否需要修改已有提示词或指导新写，需要进一步决定场景时再读[场景模式](references/scene-patterns.md)。交付所需文本即结束。省略未经发现的模型 ID 和提交参数，跳过账号查询、上传和生成邀约。
- **缺少必需素材。** 只索取素材或可访问链接并说明用途，例如请用户提供用作首帧的商品图。收到素材前无需追问投放、画幅、风格或声音。
- **最终设置或已授权生成。** 按下方流程准备。用户只要求确认前的方案时，展示方案后等待。提交按共享任务生命周期处理。
- **已有任务。** 查状态或展示结果均按共享任务生命周期处理。

准备生成且首次使用或 UI 缺失时，先执行[共享 MCP Apps 检查](../kling-ai/SKILL.md#mcp-apps-首次使用检查)，再继续生成流程。

## 实时 V4 能力

选择任何生成模型前，遵循[能力发现](../kling-ai/references/capability-discovery.md)与[模型参数](../kling-ai/references/model-parameters.md)。主体库、动作库和上传操作遵循[素材流程](../kling-ai/references/asset-workflows.md)。这些实时规则优先于静态模型示例。

用户未指定模型，且当前账号返回满足要求的 V4 时，明确说“推荐使用 V4”。普通交付优先完整质量 V4，速度或成本优先时选择兼容的 V4 Flash。尊重用户指定模型。先读[视频模型路由](references/model-routing.md)，同时发现 `text_to_video` / `image_to_video` 和 `omni_ref_video`，纯文本请求也须检查全能参考。固定实时工具与模型配对，不猜模型 ID，不跨工具搬用模型；明确要求 V4 时不得静默降级。

全能参考仅使用所选模型声明的图片、视频、音频、Element 和关键帧组合。检查 `elementSupport`、`combinedItemCaps` 及 `enable_audio` / `keepOriginalSound` 互斥。`prefer_multi_shots` 单值枚举不代表镜头数量保证，不得为单镜头意图传入非法值。实时定义声明按秒计费且包含输入视频时长时，确认前说明两点，不编造单价。

## 使用约定

- 使用宿主管理的 OAuth。绝不请求或暴露 API key、token、cookie、授权头或签名 URL。
- 最终设置、额度说明和明确授权遵循[共享任务生命周期](../kling-ai/references/tool-workflows.md)。
- 每个已批准的意图只提交一次。绝不自动重试失败或结果不明确的生成。
- 在运行时发现实时工具和模式定义。不要根据示例硬编码模型名称、输入角色、时长值或多镜头字段。
- 需要时，通过远程上传工具上传附带媒体，并保留准确的返回引用。

提交、重试或查询前阅读[共享任务生命周期](../kling-ai/references/tool-workflows.md)；需要核对字段时再读[MCP 输入输出契约](../kling-ai/references/mcp-contract.md)，以当次 `tools/list` / `who_am_i` 为准。

## 工作流程

充值后续跑时，先按[恢复流程](../kling-ai/references/tool-workflows.md#灵感值不足后的恢复)处理已有任务，再判断能否准备新提交。

1. 记录用户要求的模型或系列、时长、画幅、分辨率、数量、声音、镜头结构和每项素材角色。只追问会实质影响结果的缺失信息。同一目标创建或复用 UUIDv7 `taskTraceId`。
2. 通过 OpenClaw 发现候选工具，再用 `who_am_i` 核对模型。按视频路由筛选同时满足所有要求的配对，再决定推荐项。首帧须绑定声明的首帧输入。静音要求在排序前检查，纯文本全能参考也纳入筛选。没有合适配对时说明未满足的要求并停止，仅在用户允许时考虑其他模型。
3. 通过宿主读取所选工具的完整实时 `inputSchema`，按[模型参数](../kling-ai/references/model-parameters.md)逐项绑定用户明确指定且受支持的设置。选定配对后再准备媒体。必需素材上传失败时停止。
4. 每次准备新生成、编辑或变体时，阅读[运动与镜头规划](references/motion-and-shots.md)，逐字复用已达标的提示词，按需局部修改或新写。需要进一步决定场景时再读[场景模式](references/scene-patterns.md)。纯查询和已授权的原参数重试无需重做提示词。
5. 检查实际请求的顶层 `model`、必填提示词和首帧槽位。用户明确要求 `1080p` 等规格时，核对同一入口和模型的分辨率枚举及适用条件。按共享任务生命周期展示方案，在授权和余额预检后提交一次。

## 生成模式

| 用户意图 | 模式 | 必须采用的理解方式 |
| --- | --- | --- |
| 文生视频 / text-to-video | 生成 | 不使用源图控制首帧。根据文字定义开场构图。 |
| 图生视频 / image-to-video | 图生视频 | 一张或多张图像用于控制首帧、尾帧、身份或产品参考，或者视觉参考。明确指定每项输入的角色。 |
| 动作控制 / motion control | 动作迁移 | 主体图必填；动作库 `motionId` 与动作来源视频二选一，其余参数以实时模型定义为准。 |
| 多镜头 / storyboard | 单条已批准的视频方案 | 有意识地划分时间和连续性；除非用户明确批准生成独立任务，否则不要为每个镜头分别提交任务。 |
| 查进度 / status | 只读 | 不调用生成工具；查询已有任务。 |

对于图生视频，提交前应区分以下角色：

- **首帧：**锁定开场构图，并以它为起点向后生成动态；
- **尾帧：**只有在实时模式定义支持时，才用于规定目标画面；
- **身份或产品参考：**保留主体事实，但不假设输入就是首帧；
- **风格参考：**只迁移明确指定的视觉特征，不迁移身份或构图。

当上传、参考图数量或模式定义校验失败时，不要静默地从图生视频降级为文生视频。报告限制，并让用户修改请求。

调用工具前，在内部检查所选模式、参考图角色、时长、分辨率、镜头结构和受保护元素，随后遵循共享任务生命周期的授权规则。

## 质量优先的默认策略

- 普通成片默认使用 `1080p`；高质量、商用、大屏或后期需求在实时模型支持时使用 `4k`；只有草稿、快速或成本优先时使用 `720p`，或者目标模式仅支持 `720p`。不要把模型更高的默认分辨率主动降级。
- 一个动作或一个镜头使用 `5` 秒；对白、演唱、完整产品动作或两个相连节拍优先 `10` 秒；复杂叙事只在实时模式支持且确有必要时使用更长时长。选择能完成内容的最短时长。
- 文生视频根据投放位置选择画幅：竖版短视频用 `9:16`，方形信息流用 `1:1`，横版广告、网页或 YouTube 用 `16:9`；没有投放上下文时才用 `16:9`。
- 即使提供首帧，也要传入用户明确指定且受支持的画幅。未指定时保留首帧构图，实时工具要求比例时再选兼容值。
- 单一时刻优先使用一个连续镜头。只有在明确存在叙事推进、多个地点或时间，或者用户要求一个序列时，才使用多镜头。
- 保持首次生成目标集中。不要添加用户未要求的旁白、画面文字、额外角色或产品功效。

## 质量门禁

提交前，检查主体动作能否在指定时长内完成、镜头指令是否冲突、首尾帧意图是否清晰、参考身份或产品结构是否受到保护，以及多镜头时长能否组成连贯整体。对于广告和讲解视频，确保每个镜头只承担一项传播任务。

## 失败处理

- 授权失败：引导用户使用 OpenClaw 原生 MCP 连接流程。
- 参数或模型无效：刷新实时模式定义，只修改不受支持的字段。
- 图生视频或全能参考返回资源无效：按[素材引用失败](../kling-ai/references/troubleshooting.md#上传或素材引用失败)检查首帧和参考素材；源图片或参考作品的编号只用于查询源素材。
- 灵感值不足：按[恢复流程](../kling-ai/references/tool-workflows.md#灵感值不足后的恢复)保留原模型、规格、提示词和素材；用户明确继续时核对原首帧槽位及素材有效性。
- 响应丢失：按共享任务生命周期恢复或报告未知，不得盲目重放生成调用。
- 提供方失败：报告消息并保留各项 ID；绝不自动重新提交。
