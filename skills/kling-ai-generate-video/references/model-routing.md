# 视频入口与模型选择

先遵循[能力发现](../../kling-ai/references/capability-discovery.md)，工具存在不代表某个模型可用。

| 完整发现结果 | 路由 |
| --- | --- |
| 无 `omni_ref_video` | 按意图与实时模型能力使用 `text_to_video`、`image_to_video` 或 `motion_control`，这些入口返回的新模型也有效。 |
| 存在 `omni_ref_video` | 与相关视频入口共同查询模型，纯文本也包含它；用户要求优先，在兼容候选中推荐 V4。 |
| 没有兼容 V4 | 普通请求保留兼容入口及可用默认模型，说明原因；需要全能参考能力时选择实际支持且返回的模型。 |
| 发现失败或明确请求不可满足 | 排查或说明限制，不静默降级、不删素材、不通过付费生成探测。 |

当前账号返回兼容模型时说“推荐使用 V4”，普通交付优先完整质量 V4；速度或成本优先时选择兼容 V4 Flash。使用实时规范名，不猜 ID、不称“最新模型”，不因 V4 增加数量或分辨率。

- 纯文本可用全能参考的前提是所选模型允许无媒体输入，否则选兼容文生视频模型。
- 图片、视频、Element、音频及其组合必须由所选模型支持，工具级描述不等于每个模型的能力。
- 关键帧使用声明相应槽位的工具/模型，不固定到某一入口，不发明中间帧或用身份参考代替帧控制。
- 动作迁移须明确支持该意图；保留主体图和唯一动作源要求。
- 工具/模型配对不可分割，不能把全能模型传给其他入口。

选择后执行[模型参数](../../kling-ai/references/model-parameters.md)的条件上限、主体绑定与音频互斥规则。多镜头仍是一条确认任务，除非用户批准拆分。实时定义声明按秒且包含输入视频时长计费时，两点都要在提交确认前说明，不猜单价。
