# OpenClaw 故障排查

## 缺少工具或未授权

由操作者按包根 README 使用 `openclaw mcp add` 配置唯一的 `kling-ai` 服务，再执行 `openclaw mcp login kling-ai`。OpenClaw 2026.9.4 的 `mcp login` 从操作员管理的 MCP 配置读取目标；插件清单中的同名服务仍用于 Agent Runtime。使用 `openclaw plugins inspect kling-ai` 检查 Bundle，再用 `openclaw mcp doctor kling-ai --probe` 检查已保存的连接。不要请求 API key、token、cookie 或完整授权头。

当前本机 OpenClaw 2026.9.4 使用 `OpenClaw MCP` 作为动态注册 client_name。若服务端拒绝注册或回调，报告脱敏错误；不要编造 client_id、oauth_resource、scope 或另建授权代理。

## 任务与结果

提交超时或通用「服务暂不可用」提示按服务异常处理，即使外层错误码为 `InvalidParameter`。有本次 `generationId` 时走[已有任务流程](tool-workflows.md#4-只保留一个刷新所有者)，没有编号且提交结果不明确时保留 `taskTraceId`，报告创建或计费状态待确认。只有实际错误指向具体字段时才进入参数校验。

App 已挂载时由 App 刷新，模型不重复查询；没有 App 时返回文本回落和至多一个主结果链接。不要把视频封面当成视频，不把受理状态当成完成。历史素材链接可能过期，按实时工具契约刷新已有任务结果；无法恢复时要求重新提供素材。

生成队列已满时，按服务返回说明是否排队并保留设置和已知编号；用户要求继续时先处理已知原任务。查询遇到限流时返回编号和最近一次确认的状态，结束本轮查询。灵感值不足时按[恢复流程](tool-workflows.md#灵感值不足后的恢复)区分提交前暂停、服务明确拒绝和状态待确认。

## 参数或规格校验失败

- 检查实际请求的顶层 `model` 是否缺失或为空，再对照实时定义检查 `arguments[]` 中的必填参数及 `inputs[]` 槽位。`image_1` 与 `first_image` 以所选模型声明为准。
- 规格被拒绝时，用同一连接刷新对应入口及模型的 `who_am_i`，比对实际提交值、枚举和适用条件。提交值符合实时声明仍被拒绝时，记录脱敏字段和 `taskTraceId`。用户明确指定的规格不可用时请用户选择，不静默降档或重提。
- 排查字段变化时，比较同一轮可取得的模型原始工具参数、OpenClaw 实际 MCP 请求及当轮工具 Schema 的 `required`，标记缺失的采样点。只保留脱敏信息。

## 上传或素材引用失败

只使用当前模型接受的素材引用。只有实时上传工具及宿主实际支持文件读取和上传时，才执行上传；本地路径不能冒充远程图片 URL。参数和模型值以实时 schema 为准。

- 错误指向素材槽、引用或签名时，按[上传规则](asset-workflows.md#上传)核对实际输入及上传成功响应。尚未发出生成调用时，可修正引用后按正常提交规则继续。
- 提示「用同一生成 ID 重试」时，只有确认属于本次提交的 `generationId` 才能用于恢复状态；已有 widget 时沿用其刷新，否则按[已有任务流程](tool-workflows.md#4-只保留一个刷新所有者)查询。源图、上传响应或其他步骤的编号不能替代本次编号。没有可确认的编号时，保留 `taskTraceId`，报告创建及扣费状态待确认后暂停。
- 定位 URL 变化时，比对同一轮可取得的上传成功响应、模型工具参数与 OpenClaw 实际 MCP 请求。只保留脱敏的 URL 摘要和查询参数名，标记缺失的采样点。`ResourceNotFound` 本身无法确定故障位置。

## 模型能力不一致

V4 未出现时，完成包含 `omni_ref_video` 的相关视频入口发现；重连或权益变化后刷新 `who_am_i`。过滤结果不能证明未查询工具不支持，只报告当前连接未返回兼容模型，不声称账号无权限、不猜模型 ID、不提交付费探测。
