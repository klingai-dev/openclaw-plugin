# 当前账号的能力发现

生成或推荐模型前阅读本文。查状态、额度和素材库不需要模型发现。

1. 通过宿主完整发现当前连接的工具，处理分页；只调用实际暴露的工具。`tools/list` 是宿主协议，不是假定模型可调用的工具。发现失败不等于工具不存在，不能回退到旧能力。
2. 若实时 `who_am_i` schema 声明 `tools` 过滤，传入非空的相关生成工具集合；否则读取完整响应。不发明模型过滤字段。
3. 当前账号的 `availableModels` 和各工具 `models` 是模型权限与能力依据。仅匹配返回的规范名或声明别名；工具存在、会员等级、示例及 `defaultModel` 本身不能证明模型可用，默认模型也必须在返回集合中。
4. 请求模型未出现时，检查其余已发现且适合目标输出的工具。过滤结果不能证明未查询工具没有该模型。不要把视频模型用于图像生成，不因此声称账号权限不足。
5. 固定工具/模型配对后，按[模型参数](model-parameters.md)构造请求，不能跨工具搬用模型或字段。

## 视频候选集

文生视频同时检查 `text_to_video` 与已发现的 `omni_ref_video`；图生视频或关键帧同时检查 `image_to_video` 与全能参考。纯文本也检查全能参考，附件是否必填由所选模型定义。只搜索旧入口不算完成候选发现。动作迁移保留主体图片与唯一动作源要求。详见[视频模型路由](../../kling-ai-generate-video/references/model-routing.md)。

## 选择与刷新

- 用户指定且兼容的模型优先。未指定视频模型时，当前账号返回兼容 V4 才说“推荐使用 V4”。普通交付优先完整质量 V4；草稿、速度或成本优先时选择兼容 V4 Flash。模型 ID 仅来自实时规范名或别名，不说“最新模型”。
- 普通请求没有兼容 V4 时，保留已有兼容入口及其可用默认模型并说明原因；明确要求 V4 时不静默降级。图像继续使用实时图像模型，不从视频支持推导 V4 图像模型。
- 素材、时长、音频及预算要求优先于版本偏好；不得删除素材、增加数量或降低规格来适配模型。
- 同一准备过程复用成功发现结果。重新连接、切换账号/区域、权益变化、能力通知或参数被拒绝后刷新；候选集扩展时查询剩余工具。
- 完整发现仍未返回请求模型时，只报告当前连接未返回它。用户表示已开放时按[故障排查](troubleshooting.md)刷新，不能猜模型 ID 或通过付费生成探测。
- 模型能力来自 `who_am_i`，请求结构来自工具 `inputSchema`。示例不能扩大能力；冲突时刷新，无法同时满足则提交前停止。
