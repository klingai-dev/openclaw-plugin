# 远程工具工作流

本文件是生成任务生命周期的单一事实源。图片与视频 Skill 只补充创作和参数选择，不得另行定义提交、查询或完成语义。

## 1. 先判断用户要做什么

| 当前意图 | 已知状态 | 动作 |
| --- | --- | --- |
| 创建新作品 | 当前目标没有已提交或结果不明确的生成 | 准备最终设置并取得明确授权后调用一次生成工具 |
| 明确重试或新变体 | 用户为下一次尝试给出新的明确授权 | 同一目标复用 `taskTraceId`，调用一次生成工具 |
| 充值后明确继续 | 当前会话有因余额暂停的请求 | 按[灵感值不足后的恢复](#灵感值不足后的恢复)处理 |
| 查看、继续等待或查进度 | 已有 `generationId` | 走已有任务流程，不调用生成工具 |
| 提交响应不明确 | 没有可确认的任务结果 | 按下方歧义规则处理，无任务编号时报告未知并停止 |

“再看看”“继续”“现在好了吗”“展示结果”默认指向已有任务。余额不变或历史中未显示任务，均不足以证明上次未创建或未计费。再次提交须为最终设置取得新的明确授权。

## 2. 提交一次

1. 为一个新用户目标创建 UUIDv7 `taskTraceId`，已有目标复用原值；切换到无关目标时才创建新值。
2. 通过宿主发现当前区域工具；生成或动作控制前按[能力发现](capability-discovery.md)调用 `who_am_i`，同一准备过程复用有效结果。在该目标的发现、上传、生成、明确重试和查询中复用同一 `taskTraceId`。
3. 上传媒体后原样复用提供方引用。只传目标工具和模型实时声明的字段、类型、枚举和数量。
4. 在调用前完成模式、必填输入和参数校验，避免用一次真实调用发现本可提前识别的错误。
5. 展示适用的模式、模型、提示词摘要、分辨率或尺寸、画幅、时长、数量、镜头结构和素材角色。说明会消耗可灵额度，并提供实时工具或模型要求的计费说明。同一意图尚未提交且最终设置未变时沿用已有明确授权，一般性的生成请求、上传、素材库操作或额度查询均不构成对最终设置的授权，此时等待确认。
6. 获得授权后，紧邻收费提交用同一连接查询 `query_membership_and_credits`。未取得本轮余额时保留任务、暂停提交，并说明余额暂不可确认。余额非正数、服务明确提示余额不足，或同一设置的实时预计消耗超过余额时，按下方流程暂停。余额为正但没有实时成本时，不声称一定充足。只读状态或素材查询无需查余额。
7. 通过预检后调用生成工具一次。工具拒绝也计作一次尝试。保留返回的 `generationId`、`taskTraceId` 和原始状态。服务拒绝原因是余额不足时，按下方流程暂停。

### 灵感值不足后的恢复

1. 在当前会话保留原意图、工具、规范模型 ID、提示词、规格、素材槽位、可用素材引用、`taskTraceId`、提交状态及已知的 `generationId`。区分提交前暂停、服务明确拒绝和提交结果待确认。仅在服务返回同一设置的实时预计消耗时说明差额。
2. 优先提供当前连接返回且适用于该区域的官方充值入口；未返回时，引导用户在[国内可灵官网](https://klingai.com/)登录同一账号充值。由用户完成充值，并回到当前会话说「继续刚才的任务」。只说已充值时查余额，等待用户明确继续。
3. 明确继续时，恢复当前会话中唯一可确定的原请求；有多个候选时只问要继续哪一个。已有本次任务编号时，先按[已有任务流程](#4-只保留一个刷新所有者)使用已挂载的 widget 或查询原任务一次。此前未发出生成请求，或服务明确确认未创建且未扣费，才可新提交。提交结果仍不明确时按歧义规则停止。
4. 在原账号核对模型、原规格和素材有效性，复用 `taskTraceId`。原素材引用仍有效时直接复用，过期时从当前可访问的源素材重新取得引用；只请用户补无法恢复的素材。原设置已获确认且未变更时，明确要求继续即授权按原设置提交一次。需要变更模型或付费设置时先取得用户选择。按提交步骤重新查余额，条件满足后提交一次。余额仍不足时继续保留原请求。

## 3. 区分受理、处理中和完成

- 报告提交或查询结果时，使用实际返回的状态、已知任务编号及展示规则允许的链接。能确认实际生效的设置时一并说明。
- 含 `generationId` 的即时响应表示任务已受理或创建，不表示作品完成。
- 只有工具返回实际扣费金额或点数时才报告扣费，例如 `creditsConsumed`。涉及计费但工具未返回扣费时，说明扣费未知。提交次数和本地工具调用限额均不能换算成可灵额度，扣费也不证明作品已完成。
- 非终态只说“已提交”或“处理中”。
- 任务终态失败时报告提供方消息并保留 ID，不自动重试。
- 任务终态成功，且可用作品的媒体类型和数量满足本次任务要求时，才报告全部完成。只返回部分可用作品时，按下方展示规则交付已有作品并报告实际数量，例如「已生成 2/3 张」。目标数量未知时，报告已确认的作品数。
- 终态成功但没有可用作品属于输出不一致。报告事实并保留 ID，不创建替代任务。

## 4. 只保留一个刷新所有者

| 场景 | 模型动作 |
| --- | --- |
| OpenClaw 已挂载本次生成 widget | 不调用 `query_tasks` 或 `query_result`；widget 内部刷新并原位展示 |
| 没有 widget，生成调用刚返回 | 返回当前状态、任务编号和文本回落；不进入模型轮询循环 |
| 用户之后明确查询状态或报告结果未出现，且无已挂载 widget | 有本次 `generationId` 时调用一次无 UI 的 `query_tasks`，报告该次快照 |
| 用户之后明确展示已有任务 | 实时存在 `query_result` 时调用一次以挂载 widget；否则调用一次 `query_tasks` |

已挂载 widget 是唯一媒体预览。不要在它外部重复添加 Markdown 媒体、附件、缩略图、卡片或下载链接。

查询返回资源无效、限流或其他异常时，保留任务编号并说明未能刷新。报告最近一次确认的状态，例如「已提交」或「处理中」；从未确认过状态时报告「状态待确认」。结束本轮查询，不重提生成。

## 5. 归一化结果

1. 任务和作品状态按大小写不敏感处理，终态集合以实时 schema 或响应说明为准。
2. 作品级 `status` 存在时，仅计入成功作品；缺失时依据任务终态和可用媒体。只计入符合目标媒体类型且有可用主媒体的作品。
3. 主媒体优先 `urlWithoutWatermark`，其次 `url`。不要按数组第一项盲选。
4. `coverUrlWithoutWatermark` 和 `coverUrl` 只用于封面或缩略图；视频只有封面时不算产生视频成品。
5. 无 widget 时说明成功作品数量，并最多返回一个主作品链接；签名 URL 不写日志，也不当作永久资产 ID。

## 6. 处理歧义与重试

- 已取得 `generationId`：按[已有任务流程](#4-只保留一个刷新所有者)使用已挂载的 widget，或在当前请求需要时查询一次。
- 本次提交未返回且没有已知的 `generationId` 时，保留 `taskTraceId`，报告实际错误及尚无法确定的创建或计费状态，然后停止。`query_tasks` 需要任务编号，无法列出历史或按追踪 ID 查找，因而无需调用或建议查询。查询响应省略 ID 时，仍保留先前已知的任务编号。
- 不自动重放。任何下一次提交都需要新的明确授权。
- 用户明确重试同一目标时复用该目标的 `taskTraceId`，新生成会获得新的 `generationId`；无关目标才使用新 `taskTraceId`。

停止条件：完成一次授权生成、返回一次明确查询快照、交由已挂载 widget 刷新，或报告无法恢复的未知状态后，结束当前动作。
